## 2. Assessment of Failed PR #89 Premise

PR #89 prevented accessor property reads during unauthenticated and metadata path processing by introducing `ownStringDataProperty` helpers. However, on authenticated paths, PR #89 retained the following statement in `src/projectos-mcp-handler.js` (line 535):

```javascript
const current = await actorFor({ ...request, headers: { ...request.headers, authorization } }, dependencies);
```

### Analysis of Object Spread Syntax `{ ...request }`
In ECMAScript, object spread syntax `{ ...request }` iterates over all enumerable own properties of `request` via `[[OwnPropertyKeys]]` and executes property accessors via `[[Get]]`. On Express and Vercel serverless request objects, framework properties (such as `req.query` or `req.url`) are attached as getter accessors.

When `{ ...request }` evaluated on authenticated requests, JavaScript invoked every enumerable getter accessor on the Vercel request object. In Node.js / Vercel serverless environments, reading these accessors invoked legacy URL parsing methods, emitting `DEP0169` deprecation warnings (`Incompatibilities with the url.parse() API`) into production runtime logs at `2026-08-21T07:43:55Z` and `2026-08-21T07:44:14Z`.

PR #89's tests covered only metadata and unauthenticated paths (where line 535 was never reached), allowing the authenticated path accessor enumeration to bypass test coverage.

## 3. Evaluation of Candidate Fix (PR #106)

### Source Changes (`src/projectos-mcp-handler.js`)
PR #106 modifies line 535 in `src/projectos-mcp-handler.js`:

```javascript
// Before (PR #89 / Main):
const current = await actorFor({ ...request, headers: { ...request.headers, authorization } }, dependencies);

// After (PR #106):
const current = await actorFor({ headers: { authorization } }, dependencies);
```

### Actor Input Scope and Authentication Semantics
`actorFor(request, dependencies)` delegates authentication and authorization to internal dependencies:
1. Calls `authorizationHeader(request)` to extract `request.headers["authorization"]`.
2. Passes `authorization` to `dependencies.authenticator.authenticate(header)`.
3. Passes `dependencies.organizationId`, `identity.userId`, and `identity.accessToken` to `dependencies.membershipResolver.resolve(...)`.
4. Verifies active organization membership (`owner`, `admin`, `operator`, `member`, `viewer`), user ID alignment, and organization ID alignment.

`actorFor` reads exclusively `request.headers["authorization"]`. Providing an explicit minimal object `{ headers: { authorization } }`:
- Prevents object spread from enumerating Vercel/Express request accessors.
- Eliminates `DEP0169` log emissions entirely.
- Fully preserves all authentication, bearer token verification, organization membership resolution, user matching, active role verification, and downstream tool OAuth scope assertions.
