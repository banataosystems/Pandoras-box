# Pandora Mobile 0.3.0 RC1 — Exact-head gate

**Artifact classification:** governance evidence / test-only
**Production release:** false

This record intentionally changes the pull-request head after the immutable exact-head gate workflow was introduced so that all required verification workflows execute against one final candidate SHA.

The candidate must not advance merely because source exists or a build completes. The exact same SHA must satisfy:

- Pandora mobile integration, including transparent-mark verification, Flutter formatting, analysis, automated tests, web release build, Android debug build, and route visual-evidence generation;
- ProjectOS Security Regression;
- the immutable exact-head evidence gate that binds the preceding workflow results to the candidate SHA.

A passing exact-head gate establishes only the **tested** proof stage for the source candidate and test artifacts. It does not establish deployment or production verification.

Remaining gates are independent different-vendor review of the exact SHA, human inspection of route screenshots and artifact manifests, physical Android installation and authenticated owner journey, authorized production promotion, post-promotion verification, and preserved rollback evidence.
