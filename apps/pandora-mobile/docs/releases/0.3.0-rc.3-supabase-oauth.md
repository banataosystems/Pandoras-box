# Pandora Mobile 0.3.0-rc.3+6 — Supabase OAuth owner-test candidate

Artifact class: owner-test pre-release only.

## Source objective

Add Supabase as a first-class OAuth provider connection in the outcome-first Pandora owner experience without putting OAuth credentials in the Android application.

## Implemented source

- Owner-facing **Connect Supabase** / **Reauthorize Supabase** flow.
- Authorization code + PKCE start state generated server-side.
- Canonical callback: `https://jcyqixttuebxqqfkjonq.supabase.co/functions/v1/connect-supabase/oauth2/callback`
- OAuth client secret is resolved only from Supabase Vault under `pandora_supabase_oauth_client_secret`.
- Access token, refresh token, and PKCE verifier are Vault-backed.
- OAuth token refresh occurs inside the Supabase control plane before an expiring OAuth access token is returned to Pandora's provider adapter.
- OAuth connection defaults to read-only governance (`allow_mutations=false`) until a separate governed mutation authority is explicitly established.
- Existing Supabase PAT installations are preserved as recovery paths; they are not the preferred owner connection.
- Mobile Connections refreshes after the external consent browser returns.
- No raw OAuth token, client secret, prompt, or customer content is emitted to analytics.

## Proof required before any completion claim

1. Exact-head formatting, static analysis, unit tests, architecture/security tests.
2. Source/provider migration integrity on MCPMaster Meta Staging.
3. `connect-supabase` Edge Function deployed to staging with JWT gateway disabled only for the callback function itself.
4. Exact OAuth app redirect URI registered in Supabase.
5. Real owner consent journey produces a new `auth_mode=oauth` Supabase connector without exposing secrets.
6. Management API organization/project discovery succeeds with the OAuth token.
7. Forced/near-expiry refresh rotates Vault-backed tokens without returning refresh/client secrets to the owner client.
8. Android package identity and sensitive-permission checks pass.
9. Physical authenticated Android owner journey passes.

## Explicit non-claims

- No production release or production provider promotion is authorized by this candidate.
- No store-eligible signing is claimed.
- No Supabase mutation authority is enabled merely because OAuth is connected.
- The OAuth connection is not considered production-verified until the real consent/callback flow and refresh path pass.
